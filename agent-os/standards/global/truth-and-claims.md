# Truth and claims

## Authority

Read `CLAUDE.md` first. It controls current product claims, publication state, approvals, and protected records.

## Rules

- Separate verified facts, inferences, and unknowns.
- Cite external factual claims with current primary sources when the task depends on them.
- Tie repository claims to a file, test, commit, pull request, provider response, deployment, or direct production check.
- Keep visible copy and structured data consistent.
- Change a review date only after the represented content and destinations were reviewed.
- State calculator assumptions, inputs, units, rounding, and limitations.
- Never invent expertise, consensus, popularity, availability, approval, revenue, demand, conversion, customers, testimonials, provider readiness, deployment state, or outcomes.
- Never convert configuration presence into proof that a live path works.
- Preserve owner-approved attribution. Do not expose private identity or account data.

## Reporting vocabulary

Use:

- Verified
- Inferred
- Unknown
- Blocked

Avoid language that implies a later release stage than the evidence proves.
